## 0. 한 장 요약 — 결론부터

1. **9단계 중 1·2·8의 일부·9의 일부는 이미 공개돼 있다.** 특히 8단계(신규 적재 / 버퍼 회수 /
   컨베이어 감속·정지 중 선택)는 [M1] 청구항 9~11로 **거의 그대로 청구돼 있다.** 여기를 차별점으로
   내세우면 안 된다.
2. **핵심 차별 후보는 3~7단계, 즉 "임시 팔레트에 놓기 전에 그 배치에서 회수가 가능한지를
   후보별로 가상 회수하여 검증한다"는 부분이다.** 두 문헌은 **버퍼(저장 영역) 배치를
   "빈 자리 찾기 + 선반 제약 + 공간 효율"로만 결정**하며, 회수 가능성을 배치 선택의
   **탈락 조건으로 쓰는 기재가 없다.**
3. **다만 이것을 "신규성 있음"으로 곧바로 읽으면 안 되는 구조적 이유가 있다.**
   두 문헌의 실시예에서 버퍼는 **선반(shelf) 위에 "하나 옆에 다른 하나" 횡방향으로 놓는
   비적층 구조**다([M1] 청구항 7, [0127]). 이 구조에서는 박스가 서로를 가리는 일이 원리적으로
   드물어서 **회수 가능성 검증이 필요하지 않다.** 즉 "안 했다"기보다 "그 문제가 발생하지 않는
   구조를 골랐다"에 가깝다. 진보성 심사에서 "임시 팔레트에 쌓는 구성으로 바꾸면 가림 검사는
   당연히 따라온다"는 반론이 나올 지점이며, **이 반론에 대한 대비가 이 발명의 최대 리스크다.**
4. **침해(FTO) 관점은 별개로 나쁘다.** [M1]·[M2] **청구항 1은 저장 영역을 선반으로 한정하지
   않는다.** "플랫폼과 상이한 저장 영역"이라고만 쓰여 있으므로, 우리의 임시 팔레트도 문언상
   저장 영역에 해당할 수 있다. 우리 절차 전체는 [M1] 청구항 1의 구성을 **포함한 위에** 검증
   단계를 더한 형태여서, 실시하려면 [M1]·[M2]의 존속기간·권리범위를 별도로 따져야 한다.
5. **AI 선행조사 보고서(2건, 260909)에는 원문과 어긋나는 판정이 있다.** 특히
   "바코드 기반 버퍼 연계" 보고서는 [M1]에 대해 구성 1~6 **전부를 ◎(명시적 개시)**로 표시했는데,
   그중 구성 4(가림 관계 고려한 임시 팔레트 배치)와 구성 5(센서 오차 반영 복구 동작)는
   **원문에서 근거를 찾을 수 없다.** §4에서 근거와 함께 반박한다.
6. **새 위협 문헌 — 심보틱 KR 10-2934201 B1은 "청구항으로는 무해, 상세설명으로는 위험"이다.**
   청구항 18개 전문을 확인한 결과 **버퍼·임시 저장·회수가 전혀 없고**, 전부
   **"배치(placement) 시퀀스 유연성"**으로 입력 대기열의 순서 오류(mis-queue)를 흡수해
   일정한 배치 속도를 유지하는 내용이다. **침해(FTO) 위험은 낮다.**
   그러나 AI 보고서가 인용한 상세설명(유연성 시퀀서(297)의 케이스 간섭 검사, 순차 제거,
   안정성 점수)은 **"쌓는 순서를 역방향으로 하나씩 지워 가며 도달 가능성과 안정성을 검사한다"**는
   기법으로 읽힌다. **쌓는 순서를 거꾸로 읽으면 꺼내는 순서**이므로, 심사관이
   "가상 회수는 이 기법의 방향만 바꾼 것"이라고 볼 수 있다. **진보성 리스크는 높다** (§6-1).

7. **★ 2차 KIPRIS 조사(§7)에서 D1·D2·D5가 크게 약해졌다.**
   - **D1·D4**: **HD한국조선해양 KR 10-2008-0088944**(소멸)이 **"간섭 없이 반출 가능한 블록을
     검색 → 반출 경로를 그리드에 마킹 → 반출되었다고 가정 → 다시 검색"**을 청구항 2에
     그대로 갖고 있다. **가상 회수의 반복 골격 자체가 2008년에 국내 공개돼 있다.**
   - **D2**: **심보틱 KR 10-2025-0043453 A**(공개)가 **"공동(void)에 기인한 안정성의 정도를
     결정하고 임계값 이상으로 최적화"**를 청구항 1에, **지지 다각형·격리 반경 기반 안정성 정의**를
     청구항 6에 갖고 있다.
   - **D5**: **브릴스 KR 10-2901586 B1**(등록)이 청구항 5에 **"센서로 최종 적재 상태를 확인하고
     정렬 구조와 다르면 점검"**을, 청구항 3에 **"버퍼 공간에 임시 적재"**를 갖고 있다.
   - **깨끗하게 남은 것은 D3(회수 시 그리퍼 접근·파지 가능성)와 D6뿐이다.**
     결과적으로 이 발명의 방어선은 **개별 요소가 아니라 "적층된 임시 팔레트 + 상부 흡착 +
     외부에서 주어진 순서" 조건에서 D1~D4를 하나의 배치 결정 게이트로 묶은 결합**으로
     좁혀졌다.

8. **★★ 3차 조사(§8)에서 D1이 무너졌다 — 이 문서의 최종 결론이다.**
   **HD한국조선해양이 2008-09-09에 3건 패밀리**(적치 위치 결정 / 반출 통로 결정 /
   반입·반출 작업순서 결정, 전부 소멸)를 냈고, 그중
   - **[10-2008-0088891] 청구항 3**은 **"간섭 없이 반출 가능한 블록을 후보로 추가 + 각 후보의
     배치 상태 저장 + 휴리스틱 평가 + 하나 반출 후 새로 반출 가능해진 블록을 후보로 재추가"**,
     즉 **A\* 탐색으로 구현한 가상 회수**를 그대로 청구한다.
   - **[10-2008-0088854] 청구항 3**은 적치 위치 평가함수에 **"반출일 순서가 지켜지지 않은
     블록의 비율"에 대한 벌점**을 넣는다 — **"나중에 꺼낼 순서를 고려해 지금 놓을 자리를
     정한다"는 착상 자체가 개시돼 있다.**
   또 **애자일소다 KR 10-2022-0087726**(등록)은 **"배출 순서 정보를 가진 화물의 적재 위치
   결정 + 하역 시뮬레이션 되먹임"** 루프를 강화학습으로 청구한다.
   → **"가상 회수 검증"이라는 착상은 신규하지 않다.** 명칭·독립항을 여기에 걸면 즉시 인용된다.
   **살아 있는 것은 "물리 실행 가능성 계층"뿐이다** — 위 문헌들은 전부 **2차원 추상 모델**
   (그리드 점유 / 스택 테이블 / 계획상 공동)에서 놀고, **3D 적층 잔여 안정성(D2) ·
   상부 흡착 진입·파지(D3) · 로봇+그리퍼+들고 있는 박스의 3D 무충돌 경로(D4)를
   동시에 갖는 문헌은 없다.** §8-5가 최종 권고이며, **명칭도 §9에서 바꿨다.**

## 1. 비교 대상 절차 (9단계) — 표의 행 정의

용어를 먼저 고정한다.

- **출고 팔레트**: 목적지로 나가는 최종 팔레트. 두 문헌의 "과업 위치(116) / 플랫폼 / 팔레트".
- **임시 팔레트**: 지금 출고 팔레트에 못 넣는 박스를 잠시 쌓아 두는 곳. 두 문헌의 "저장 영역(705)"에
  대응하지만, 두 문헌 실시예는 **선반**이고 우리는 **팔레트에 쌓는다**(§3 참조).
- **선행 순서**: 어떤 박스를 어떤 박스보다 먼저 회수해야 하는지의 순서 제약.
- **가상 회수**: 실제로 옮기지 않고 계산상으로만 박스를 하나씩 꺼내 보는 것.

| 단계 | 내용 |
|---|---|
| S1 | 신규 박스의 정보와 선행 조건을 확인한다 |
| S2 | 출고 팔레트에 바로 적재할 수 있는지 검사한다 |
| S3 | 불가능하면 임시 팔레트의 배치 후보를 생성한다 |
| S4 | 후보마다 신규 박스를 **가상으로 놓는다** |
| S5 | 알려진 선후 관계에 따라 박스들을 **가상으로 하나씩 꺼낸다** |
| S6 | 매 회수 단계에서 ①그리퍼 접근·파지 가능성 ②로봇·그리퍼·들고 있는 박스의 무충돌 이동 ③제거 후 잔여 적재물 안정성을 검사한다 |
| S7 | 가능한 회수 순서와 경로를 찾은 후보만 채택한다 |
| S8 | 신규 박스 도착시간과 작업시간을 비교해 신규 적재 / 버퍼 회수 / 감속 / 정지를 결정한다 |
| S9 | 작업 후 실제 위치를 확인하고 계획을 갱신한다 |

## 판정 등급

| 등급 | 뜻 |
|---|---|
| **A. 공개됨** | 청구항 또는 상세설명에 직접 기재. 차별점으로 쓸 수 없음 |
| **B. 일부만 확인** | 비슷한 개념은 있으나 **판단 대상·시점·목적 중 하나 이상이 다름**. 그대로 차별점이라 주장하면 위험 |
| **C. 검토 범위에서 미발견** | 청구항 전문 + 상세설명 텍스트에서 대응 기재를 찾지 못함 |
| **D. 판단 보류** | 도면 미열람 등으로 확인 자체가 불가한 부분 |

C는 "존재하지 않음"이 아니라 "이번 검토 범위에서 찾지 못함"이다. 용어가 없다는 이유로 기능이
없다고 단정하지 않기 위해, C로 표시한 칸에는 **무엇을 찾았고 무엇이 없었는지**를 함께 적었다.

## 2. 단계별 비교표 (본체)

### S1. 신규 박스의 정보와 선행 조건 확인

| | 판정 | 원문 근거 |
|---|---|---|
| **[M1]** | **A. 공개됨** | 청구항 1(3쪽): 시리즈의 다음 패키지의 **패키지 ID를 결정**하고, 패키지 ID와 적층 계획으로 **시퀀스 ID를 결정**. 청구항 2(3쪽): 패키지가 로딩 장치로 향하며 **스캐닝 유닛을 지나갈 때 코드를 결정**(= 도착 전 상류 스캔). 청구항 18(6쪽): 코드 스캐닝을 하나 뒤에 다른 하나 순으로 수행. [0116](25쪽): 스캐너(715)를 지나가므로 **패키지가 시작 위치에 도달할 때까지 ID와 시퀀스 ID를 이미 알고 있다** |
| **[M2]** | **A. 공개됨** | 청구항 1(3쪽): 각 패키지에 대해 **물리적 치수를 포함하는 패키지 속성을 결정**. [0156](30쪽): 패키지 ID 결정. [0159](30~31쪽): **초기 리프트 중 힘/회전력 센서로 패키지 중량을 계산** |

**결론:** 바코드로 식별해 순서를 판정하는 부분은 **완전히 선점돼 있다.** 여기를 차별점으로
쓰면 안 된다. 다만 두 문헌의 시퀀스 ID는 **하나의 플랫폼에 대한 적재 순서**에서 나오며,
**목적지별 다중 출고 팔레트 + 주문 시스템의 배송 순서**를 입력으로 받는 구조는 이 두 문헌에서
확인되지 않았다(C). 이는 우리 설계 쟁점 "순서의 의미"(적재 순서 / 배송 순서 / 도착 순서 구분)와
직결되므로, **정보 출처 구조 자체를 청구항에 넣을지**는 별도 판단이 필요하다.

### S2. 출고 팔레트에 바로 적재할 수 있는지 검사

| | 판정 | 원문 근거 |
|---|---|---|
| **[M1]** | **A. 공개됨(단, 판정 기준이 다름)** | 청구항 1(3쪽): 시퀀스 ID에 기초해 **적층 시퀀스에서 그 다음에 있는지**를 결정. 청구항 8(4쪽): 그 다음에 있으면 **저장 영역으로 보내지 않고 플랫폼에 배치** |
| **[M2]** | **B. 일부만 확인** | 즉시 배치 판정 자체는 [M2] 청구항 1에 없다. [M2]는 "일단 저장 영역에 넣고, 팔레트화 트리거가 발생하면 꺼낸다"는 흐름이다(청구항 1, 3쪽) |

**중요한 차이:** [M1]의 즉시 적재 판정 기준은 **"순서상 다음인가"라는 단일 조건**이다.
우리 S2는 **경계·겹침·지지면적·무게중심·하중·로봇 실행 가능성까지 함께 보는 복합 게이트**다.
그런데 그 복합 게이트의 **재료는 이미 [M1]·[M2]에 다 있다**:

- **진입로 + 충돌 확률**: [M1] [0061](17쪽) / [M2] [0063](16쪽) — "각각의 배치 위치 및 대응하는
  충돌 확률에 대한 **진입로를 계산**", "충돌 확률이 미리 결정된 문턱값을 초과하는 배치를 **제거**".
- **지지 중량 / 취약도**: 같은 문단 — 배치 위치 아래 패키지의 최대 지지 가능 중량 위반 배치를 제거.
- **적층 안정성 규칙**: [M1] [0065]~[0071](17~18쪽) / [M2] [0067]~[0071](16~17쪽) —
  중첩 필요조건(422), 오버행 필요조건(424), **질량 중심(CoM) 오프셋 규칙**(402),
  지지 분리 규칙(404), 수직 오프셋 규칙(406). 명시 목적은 "**팔레트 이동 동안 패키지가
  미끄러지거나 기울어지는 것을 방지**"([M1] [0065], 17쪽).

**따라서 "출고 팔레트 적재 게이트"는 차별점이 될 수 없다.** 다만 두 문헌의 충돌 검사는
**"충돌 확률(probability)"이라는 휴리스틱 점수**이고, **로봇 역기구학(IK)·관절 한계·실제 경로
계획 성공 여부를 게이트로 쓰는 기재는 찾지 못했다(C)**. 이 구별(확률 점수 vs 실제 경로 해 존재)은
살아 있으나, 두 문헌이 "진입로 계산"이라는 표현을 쓰고 있으므로 **좁고 약한 구별**로 취급해야 한다.

### S3. 임시 팔레트의 배치 후보 생성

| | 판정 | 원문 근거 |
|---|---|---|
| **[M1]** | **B. 일부만 확인** | 청구항 4(3쪽): 저장 영역 배치를 **"배치 계획에 기초"**하여 구현. 청구항 5(4쪽): 취약도 순위·중량 범위·높이·유형에 따라 **분류**. 청구항 6(4쪽): 저장 선반의 **수·치수·높이·폭·깊이·추정된 하중 지탱력**에 기초해 분류. 청구항 7(4쪽): 저장 선반 상에서 **서로 횡방향으로 인접**하게 저장. [0127](26~27쪽): "저장 선반의 수, 저장 선반의 치수, 저장 선반의 **중량 지탱 능력** 등을 고려", "**랜덤으로 배치**할 수 있다" |
| **[M2]** | **B. 일부만 확인** | [0157](30쪽): "입수 가능한 패키지의 **또 다른 인스턴스에 의해 점유되지 않은** 저장 위치에서 파지·수송·배치" = **빈 자리 찾기**. [0158](30쪽): 선반 수·치수·중량 지탱 능력, 횡방향 배치, 랜덤 배치 |

**결론:** "임시 저장 위치를 계획해서 고른다"는 것 자체는 공개돼 있다. 그러나 후보를 만드는
근거가 **빈 자리 / 선반 물리 제약 / 분류(높이·중량·취약도) / 공간 효율**이다.
**"나중에 꺼낼 수 있는가"를 후보 생성·평가의 기준으로 쓰는 기재는 두 문헌 모두에서
찾지 못했다(C).** 가장 가까운 문장은 다음 하나뿐이며, 이것이 이 비교의 핵심 쟁점이다.

> **[M1] [0127](27쪽)**: "…패키지를 저장 영역(705)에 배치할 수 있고 저장 영역(705)으로부터
> **최대 효율로 검색할 수 있도록** 저장 영역(705)에 저장된다."
> **[M2] [0158](30쪽)**: "…하나 이상의 입수 가능한 패키지를 **저장 및/또는 검색하기 위해**
> 저장 영역 내 입수 가능한 저장 공간을 **효율적으로 사용**할 수 있도록…"

이 문장은 **"회수 효율"에 대한 서술**이지, **회수 가능성 검증**이나 **불가능 후보의 탈락**이 아니다.
목적어가 "저장 공간의 효율적 사용"이며, 검증 절차·판정 기준·탈락 조건이 전혀 제시되지 않는다.
**다만 심사관이 "회수를 고려해 배치한다는 착상은 이미 여기 있다"고 볼 여지가 있는 문장이므로,
청구항을 쓸 때 이 문장과 명확히 구별되는 한정(무엇을 검사하고 무엇을 탈락시키는지)을
반드시 명시해야 한다.**

### S4. 후보마다 신규 박스를 가상으로 놓기 / S5. 선후 관계에 따라 가상으로 하나씩 꺼내기

| | 판정 | 원문 근거 |
|---|---|---|
| **[M1]** | **C. 미발견** | 저장 영역에 대해 가상 배치 후 가상 회수를 시뮬레이션하는 기재 없음. 검토한 시뮬레이션·탐색 구조는 전부 **출고 플랫폼 적층 계획 생성용**이다: 검색 트리(374)로 배치 조합 추적([0059], 16쪽), 우선권 큐(376)로 후보 평가·스코어링([0062], 17쪽) |
| **[M2]** | **B. 일부만 확인 — 가장 근접** | 청구항 1(3쪽): "**저장 영역에 현재 저장된** 하나 이상의 패키지를 **플랫폼 상에** 배치하기 위한 **시뮬레이션된 적층 계획을 생성하거나 업데이트**하도록 시뮬레이션 기능을 실행". [0163](31쪽): 같은 내용. [0164](31쪽): "패키지가 저장 영역에 **추가되고** … **후에 시뮬레이션된 적층 계획을 되풀이하여 생성 또는 업데이트**" |

**[M2]가 왜 근접하고, 왜 같지 않은가 — 이 문서에서 가장 중요한 구별이다.**

[M2]는 확실히 **"버퍼에 뭐가 들어올 때마다, 버퍼에 있는 것들로 시뮬레이션을 다시 돌린다"**를
청구하고 있다. 즉 "신규 박스가 버퍼에 추가되는 사건을 계기로 재시뮬레이션"이라는 **시점 구조는
공개돼 있다.** 그러나 그 시뮬레이션의 **대상과 목적**이 다르다.

| | [M2]의 시뮬레이션 | 우리 S4~S5 |
|---|---|---|
| 무엇을 계산하는가 | **출고 플랫폼 위의 배열**(2D 배치 계획 → 3D 적층 계획) | **임시 팔레트에서 박스를 꺼내는 과정** |
| 목적 | **균일한 패킹층**을 달성해 위층 적층의 안정된 기저부를 만들기([0124] 25쪽, 청구항 2·5~7) | 필요한 순서로 **꺼낼 수 있는지** 판정 |
| 판정 결과 | 팔레트화 트리거 발생 여부(균일층/시한/용량/명령) | 배치 후보의 **채택·탈락** |
| 박스를 "제거"하는 계산이 있는가 | 있으나 의미가 다르다 — 배치된 패키지를 **후보 목록에서 빼서 "나머지 패키지"를 갱신**하는 것([M1] [0056] 16쪽, [M2] [0058] 15쪽). **물리적으로 꺼내는 시뮬레이션이 아니다** | 물리적 회수 1회분을 실제로 모사 |

**즉 [M2]는 "버퍼 내용물로 출고 계획을 다시 짠다"이고, 우리는 "버퍼 배치가 회수 가능한지 검증한다"다.**
이 구별은 원문 근거가 명확하다. 다만 **"버퍼 상태 변화를 계기로 시뮬레이션을 재실행한다"는
프레임 자체는 [M2]에 있으므로**, 우리 청구항은 "재시뮬레이션한다"가 아니라
**"무엇을 가상으로 제거하며 무엇을 검사하는가"**로 특정돼야 한다.

### S8. 도착시간 vs 작업시간 비교 → 신규 적재 / 버퍼 회수 / 감속 / 정지 선택

| **[M2]** | **B. 일부만 확인** | 청구항 18(5쪽): 컨베이어 장치 속도 조절. 청구항 9(4쪽): **시한 트리거** = 이송 장치의 **유휴 시간 및/또는 총 작동 시간**이 문턱값 초과. 청구항 10(4쪽): **저장 용량 트리거** |

**이 행은 방어선으로 쓸 수 없다.** "신규 처리 / 버퍼 회수 / 감속·정지" 3자 선택은 [M1]에
사실상 다 있다. 남아 있는 좁은 구별은 **판단의 트리거 방식**이다.

- [M1]의 트리거: **"다음 순서가 버퍼에 있는가"**라는 순서 조건([0128], 27쪽), 그리고
  **시작 위치에서 명시된 지속기간보다 오래 수집되지 않으면 자동 중단**이라는 타임아웃([0145], 29쪽).
- [M2]의 트리거: **유휴 시간·총 작동 시간·저장 용량**의 문턱값(청구항 9·10, 4쪽).
- **우리 S8**: **신규 박스의 도착 예정 시각**과 **기존 박스의 회수 예정 소요시간**을 **비교**.

즉 두 문헌은 **문턱값(threshold)** 방식이고 우리는 **두 시각의 비교(race)** 방식이다.
이 구별은 원문 근거상 유지되지만 **매우 좁다.** 타임아웃과 유휴시간 문턱값이 이미 있는 상태에서
"두 시각을 비교한다"가 진보성을 지탱하기는 어렵다고 본다. **S8은 종속항 소재로 두고,
독립항의 무게는 S3~S7에 두는 것이 안전하다.**

### S9. 작업 후 실제 위치 확인 및 계획 갱신

| | 판정 | 원문 근거 |
|---|---|---|
| **[M1]** | **B. 일부만 확인** | **사건 기반 재계획은 있다**: [0085](20쪽) — "예시적인 트리거링 조건은 **적층 오류(분실된 또는 떨어진 패키지), 충돌 사건**, 사전 결정된 리트리거링 타이밍"에 따라 나머지 세트의 처리 순서를 재계산. | **[M2]** | **B. 일부만 확인 — [M1]보다 근접** | [0160](31쪽): "저장 위치 정보는 **2D 및/또는 3D 센서를 사용하여 결정될 수 있는**, 저장 영역 내 패키지의 저장 위치에 대응하는 정보" = **센서로 실제 저장 위치를 확정해 저장맵에 기록**. [0159](30~31쪽): 리프트 중 힘 센서로 **중량 실측**. [0087](19쪽): [M1] [0085]와 동일한 재계획 트리거. [0164](31쪽): 버퍼 추가 후 시뮬레이션 되풀이 갱신 |

**중요:** [M2]는 **"센서로 실제 저장 위치를 확정한다"**까지 와 있다. 따라서
**"센서로 실제 위치를 확인한다"를 차별점으로 주장하면 안 된다.**
살아 있는 구별은 두 가지이며, 둘 다 원문 근거가 있다.

1. **오차를 무엇에 되먹이는가**: [M2]는 측정된 위치를 **저장맵 기록값**으로 쓴다.
   우리는 **오차가 반영된 실제 상태로 S5~S7 가상 회수 검증을 다시 돌린다.**
   "오차 → 회수 가능성 재판정"의 인과가 [M2]에는 없다(C).
2. **선행 조건 완료 처리 시점**: 우리 설계 쟁점대로 **실제 적재 성공이 확인되기 전에는 후행
   박스의 선행 조건을 완료로 처리하지 않는다.** 두 문헌은 배치 후 **시퀀스 계수기를 즉시
   갱신**한다([0117]·[0118], 25~26쪽) — 계획 기준 갱신이며 성공 확인 게이트가 아니다.

## 3. 구조적 차이 정리 — 표에 담기지 않는 가장 중요한 사실

| 항목 | [M1]·[M2] 실시예 | 우리 설계 |
|---|---|---|
| 버퍼의 물리 형태 | **저장 선반(710)**. 반원형 다수 티어(원형 경기장 구성), 계단 구성, 또는 다수의 행과 열([M1] [0126], 26쪽) | **바닥에 놓인 임시 팔레트 1개** |
| 버퍼 내 배치 방식 | 선반 위에 **"하나 옆에 다른 하나" 횡방향**([M1] 청구항 7, 4쪽; [0127], 26~27쪽), 또는 **랜덤** | 팔레트 위에 **적층(위로 쌓음)** |
| 그래서 회수 시 | 박스가 서로를 가릴 일이 원리적으로 드묾 → **가림·차단 문제가 발생하지 않음** | **아래 박스가 위 박스에 막힘 → 검증 없이는 회수 불가 상황이 실제로 발생** |
| 버퍼 배치의 결정 근거 | 빈 자리, 선반 수·치수·하중 지탱력, 분류(높이·중량·취약도), 공간 효율 | + **회수 가능성(접근·경로·잔여 안정성)** |
| 그리퍼 | 일반 엔드-이펙터 | **상부 흡착** (측면 접근 불가 → 위가 막히면 파지 자체가 불가) |

**두 방향으로 읽어야 한다.**

- **특허성(신규성) 쪽**: 두 문헌은 적층 버퍼를 전제하지 않았고, 따라서 회수 가능성 검증을
  **교시(teach)하지 않는다.** S6-①③, S7이 C인 것은 우연이 아니라 구조에서 나온다.
- **진보성 리스크 쪽**: "선반을 임시 팔레트로 바꾸면 가림 검사는 통상의 기술자에게 자명하다"는
  반론이 성립할 수 있다. **이 반론을 막는 것은 "검사한다"가 아니라 "검사 결과를 배치 결정의
  탈락 조건으로 쓴다 + 상부 흡착이라 대안 접근이 없다 + 순서가 외부(주문)에서 주어져 계획자가
  바꿀 수 없다"는 3가지 제약의 결합**이라고 본다. 실험 데이터(§7 항목 4)가 필요한 지점이다.
- **침해(FTO) 쪽**: **[M1]·[M2] 청구항 1은 저장 영역을 선반으로 한정하지 않는다**
  ("상기 플랫폼과 상이한 저장 영역", 3쪽). 우리 임시 팔레트는 문언상 여기 들어갈 수 있고,
  우리 절차는 [M1] 청구항 1의 단계들을 **모두 포함한 위에** 검증을 더한 형태다.
  **개량발명은 원발명 특허를 침해할 수 있다** — 특허성과 별개로 실시 시점에 반드시 검토해야 한다.

## 4. AI 선행조사 보고서(260909) 2건에 대한 검증 — 원문과 어긋나는 판정

두 보고서 모두 말미에 "문헌 기재 내용과의 사실적 일치 여부는 보증하지 않는다"고 명시돼 있다.
실제로 원문과 어긋나는 판정이 확인됐다.

### 4-1. "바코드 기반 버퍼 연계" 보고서 — [M1]에 구성 1~6 전부 ◎

**보고서의 구성 4** = "예상 회수 순서, 박스 간 **가림 관계** 및 로봇 접근 경로를 고려하여
먼저 회수할 박스가 다른 박스에 의해 **차단되지 않도록** 배치된 임시 팔레트" → **◎(명시적 개시)**

보고서가 제시한 이유는 이것이다.

> "저장 영역 내 패키지 배치 시 배치 계획을 생성하여 저장 선반의 수, 치수, 중량 지탱 능력을
> 고려하고, 패키지를 **검색할 때 저장 위치 정보를 사용하므로 로봇 접근 경로를 고려한다고 볼 수 있다**."

**반박(원문 근거):**
- "저장 위치 정보를 사용해 검색한다"는 것은 **어디 있는지 안다**는 뜻이다([M1] 청구항 1, 3쪽;
  [0118], 25~26쪽). **접근 경로를 검사한다는 뜻이 아니다.** [0142](29쪽)의 회수 계획은
  "검색하기 위한 명령어를 생성"까지다.
- **"가림 관계", "차단되지 않도록"에 해당하는 기재는 원문에 없다.** 오히려 [M1] 청구항 7과
  [0127](26~27쪽)은 **횡방향 인접 배치**와 **랜덤 배치**를 제시한다 — 가림을 회피하기 위한
  판정이 아니라, 가림이 문제되지 않는 구조를 쓴 것이다.
- 따라서 **구성 4는 ◎가 아니라 C(미발견) 내지 △**로 보는 것이 원문에 맞다.

**보고서의 구성 5** = "실제 적재 위치와 성공 여부를 확인하는 센서부 + 계획과의 차이를 팔레트
상태에 반영 + 재배치·팔레트 전환·컨베이어 정지·운영자 요청 복구 동작 선택" → **◎**

보고서 이유: "센서(216)가 이미징 디바이스(222) 및 위치 센서(224)를 포함하여 실제 적재 위치와
성공 여부를 확인한다" + "적층 오류나 충돌 사건을 트리거로 처리 순서를 재계산하고 컨베이어를
중단·조절하는 복구 동작을 수행한다".

**반박(원문 근거):**
- [M1] [0037]~[0040](13쪽)의 센서 서술은 **로봇 시스템 일반 구성 설명**이다. 위치 센서(224)는
  "**로봇 암 및/또는 엔드-이펙터 및 대응하는 이음부의 위치**를 검출"하는 것 — **로봇 자체의
  관절 위치 센서**이며 적재된 박스의 자세 측정이 아니다.
- [0085](20쪽)의 재계획 트리거는 **"분실된 또는 떨어진 패키지"와 "충돌 사건"**이라는
  **이산적 사건**이다. **"계획 위치와 실제 위치의 차이(오차)"를 반영한다는 기재가 아니다.**
- 컨베이어 중단은 **복구 동작이 아니라 순서 조정 수단**으로 기재돼 있다([0128], 27쪽:
  다음 순서가 버퍼에 있을 때 / [0145], 29쪽: 수집 지연 타임아웃).
- "팔레트 전환", "운영자 요청"에 해당하는 기재는 **찾지 못했다.**
- 따라서 **구성 5도 ◎가 아니다.** 단, [M2] [0160](31쪽)의 **"2D/3D 센서로 저장 위치 결정"**은
  실제 위치 확인에 해당하므로, **[M2] 쪽이 [M1]보다 이 구성에 더 가깝다** — 보고서가
  [M1]을 ◎, [M2]를 △로 준 것은 **방향이 뒤바뀐 판정**이다.

### 4-2. "가상 회수 검증" 보고서 — 내부 모순

이 보고서는 상단 비교표에서 심보틱 [KR 10-2934201 B1]의 **구성 3을 △(부분 개시)**로 표시했다.
그런데 같은 보고서의 상세 섹션은 **구성 3의 6개 세부 요소 전부에 대해 대응 기재를 제시**한다
(유연성 시퀀서(297)의 케이스 간섭 검사, 순차 제거로 매트릭스(999A/999B) 축소, 상호의존적
경로(LP), 안정성 점수 계산과 불안정 케이스 식별, 안정성·균형 점수 기반 순위·최상 솔루션 선택).
**세부 요소가 전부 채워졌는데 종합 판정이 △인 것은 일관되지 않는다.** 원문을 직접 확인하지
않은 상태에서는, **이 보고서의 △를 근거로 안심하면 안 된다.**

  제거 + 안정성 점수**가 실제로 함께 기재돼 있으면, "방향만 바꾼 적용"이라는 진보성 부정

  ① 간섭 검사가 **로봇 도달성·경로**를 보는지 **박스 간 겹침만** 보는지,
  ② 안정성 점수가 **제거 후 잔여물**을 보는지 **적층 시점**을 보는지,
  ③ 순차 제거가 **하나의 확정된 배열에 대한 역방향 탐색**인지 **여러 배치 후보 간 비교**인지.

### 7-2. ★ HD한국조선해양 KR 10-2008-0088944 — D1·D4의 최대 위협

**청구항 2(원문)의 절차**를 그대로 옮기면 이렇다.

1. 각 작업 블록들 중 **간섭 없이 반출 가능한 제1 블록들을 검색**하는 단계
2. 제1 블록이 적치장으로부터 나갈 때까지 **거쳐간 그리드(Grid)에 블록정보를 마킹**하는 단계
3. 제1 블록들을 모두 찾았다면 **제1 블록들이 반출되었다고 가정한 후**, 간섭 없이 반출
   가능한 **제2 블록들을 검색**하는 단계
4. 제2 블록의 **반출 경로 그리드에도 마킹**하는 단계
5. 제1·제2 블록의 **마킹 영역이 중복되는 경우** 선 마킹된 제1 블록에 **우선순위 부여**
6. 우선순위에 따라 **순서제약을 획득**

**이것은 우리 S5 + S6-② + S7의 골격과 사실상 동일하다.**
"가상으로 하나 꺼내고 → 꺼냈다고 가정하고 → 다음을 다시 검사"라는 반복 구조,
그리고 "**반출 경로가 서로 겹치는지**"를 판정 기준으로 쓰는 것까지 들어 있다.
IPC도 **B65G1/137**(창고 인출 순서 제어)로 우리 주제와 같은 영역이다.

**우리와 다른 점 (원문 근거로 확인됨):**

| | HD조선해양 [0088944] | 우리 절차 |
|---|---|---|
| 대상 | 조선소 **적치장의 블록**(평면 배치, 트랜스포터가 밑으로 진입) | **임시 팔레트에 적층된 박스** |
| 잔여 안정성 | **없음** — 블록은 서로 위에 쌓이지 않아 무너질 대상이 없다 | **있음(D2)** |
| 그리퍼 접근·파지 | **없음** — 트랜스포터가 아래로 진입해 들어올림 | **있음(D3, 상부 흡착이라 위가 막히면 파지 불가)** |
| 판정 결과의 용도 | **순서제약 획득**(스케줄링). 이미 놓인 배치를 전제 | **배치 후보의 채택·탈락**(배치 위치 결정) |
| 후보 비교 | **없음** — 배치는 주어진 것 | **여러 임시 배치 후보를 비교** |
| 검사 대상 | 반출 경로 **그리드 점유 중복** | 로봇·그리퍼·**들고 있는 박스**의 무충돌 이동 |

**따라서 D1을 "가상 회수를 반복한다"로 서술하면 이 문헌에 걸린다.**
살아남는 서술은 **"신규 박스를 놓을 위치를 정하기 위해, 여러 배치 후보 각각에 대해
가상 회수를 수행하고 통과한 후보만 채택한다"** — 즉 **가상 회수의 결과를 배치 결정의
탈락 조건으로 쓴다**는 부분이다. HD조선해양은 배치를 바꾸지 않는다.

법적 상태는 **소멸**이므로 **침해(FTO) 위험은 없다.** 그러나 **신규성·진보성 판단에는
소멸 여부가 무관**하다 — 공개된 기술은 영구히 선행기술이다.

### 7-3. ★ 심보틱 KR 10-2025-0043453 A — D2의 최대 위협

우선일 2022-07-18, 국내 공개 2025-03-28, **청구항 56항**.

**청구항 1의 핵심:** 저장 어레이 + 자동 패키지 운송 시스템 + 자동 팔레타이저 + 제어기.
제어기가 **취소된 패키지(scratch package)**를 등록받고,
① 해당 팔레트 층을 식별해 취소된 패키지가 만든 **공동(void)을 결정**하고,
② **그 공동에 기인한 "안정성의 정도(measure of stability)"를 결정**하고,
③ 인접 패키지의 **포즈 변경(repose)** 또는 다른 패키지와의 **교환(swapping)**으로
안정성의 정도를 **미리 결정된 임계값 이상으로 최적화**하여 공동을 해결하고,
④ 그 해결로 정의된 **팔레트 적재 재계획**을 생성한다.

**청구항 6이 특히 위험하다:**
> "안정성의 정도는 패키지의 중심 주위에 배치된 **격리 반경(containment radius)**에 비례하고,
> 이 격리 반경 내에서 모든 지점들은 패키지가 안착되는 **하위 패키지들에 의해 형성된
> 패키지의 지지대들의 경계를 이루는 다각형**에 속한다"

이는 **지지 다각형(support polygon) 기반 안정성 정량화**를 그대로 청구한 것이다.
**청구항 8**은 인접 패키지를 **점진적 포즈 변환 시퀀스**로 이동시키며 **각 변환마다
안정성의 정도를 결정**하고 **최대인 것을 선택**한다 — 후보별 반복 평가·선택 구조다.

**우리와 다른 점:**
- 공동의 원인이 **"주문 취소로 애초에 놓지 않은 패키지"**다. **이미 쌓인 것을 꺼내서
  생기는 공백이 아니다.**
- 목적이 **출고 팔레트 층의 안정성 회복(재계획)**이다. **임시 팔레트에서의 회수 가능성
  판정이 아니다.**
- **회수·경로·파지·간섭·충돌 관련 용어가 청구항 56개 어디에도 없다**(직접 계수 확인).
  "접근"은 두 아암의 **중첩 작업영역(overlapping access)** 의미다.

**그러나 "공동이 생기면 잔여 적재물의 안정성을 판정한다"는 기하 판정 자체는 동일하다.**
→ **D2를 단독 차별점으로 주장하면 안 된다.** D2는 "**꺼내는 행위와 연동된** 잔여 안정성",
즉 **회수 순서 시뮬레이션의 매 단계에서 재평가한다**는 결합 형태로만 유지해야 한다.

### 8-1. ★★ HD한국조선해양 2008-09-09 3건 패밀리 — 가상 회수 탐색의 직접 개시

같은 날 출원된 3건이 **우리 S3~S7을 거의 그대로 분담**하고 있다. 3건 모두 **소멸**(FTO 무관),

| 문헌 | 명칭 | 대응 단계 |
|---|---|---|
| KR 10-2008-0088854 | 적치장 내 블록의 **적치 위치 결정** 방법 | **S3·S7** |
| KR 10-2008-0088891 | 적치장 내 블록의 **반출 통로 결정** 방법 | **S5·S6-②·S7** |

**[088891] 청구항 3 — 가상 회수 탐색 알고리즘이 그대로 적혀 있다:**
> (A) **간섭 없이 반출 가능한 모든 블록을 간섭블록의 후보로 추가**하고 **각 후보에 대해

적치 순서 s를 생성 → 평가함수로 평가 → 더 나은 s'로 갱신(언덕오르기 탐색).

### 8-5. 조사 결론 — 방어선을 어디에 둘 것인가

**"가상 회수 검증"이라는 착상 자체는 신규하지 않다.** 2008년 HD한국조선해양이 조선소 적치장에
대해, 2022년 애자일소다가 강화학습으로, 각각 "나중에 꺼낼 순서를 고려해 지금 놓을 자리를 정하고,
꺼내는 과정을 가상으로 돌려 본다"를 개시했다. 명칭 후보를 **"가상 회수 검증 기반"**으로 두면
심사관이 이 두 계열을 바로 인용할 것이다.

**살아 있는 것은 "물리 실행 가능성 계층"이다.** 위 문헌들은 전부 **추상 모델**에서 논다 —
2차원 그리드 점유(HD조선), 2차원 스택 테이블(애자일소다), 계획상 공동(심보틱).
**어느 것도 다음 3개를 동시에 갖지 않는다:**

1. **3차원 적층물에서 아래 박스를 꺼낼 때의 잔여 안정성** (D2를 회수 단계마다 재평가)
2. **상부 흡착 그리퍼가 실제로 진입·파지할 수 있는지** (D3)
3. **로봇 + 그리퍼 + 들고 있는 박스를 포함한 3D 무충돌 경로 해의 존재** (D4)

→ **독립항은 "가상 회수를 한다"가 아니라 "가상 회수의 매 단계에서 위 3개를 AND 게이트로
검사하고, 하나라도 실패하면 그 배치 후보를 탈락시킨다"로 써야 한다.**
이 결론은 1차 주제(`docs/barcode_resequencing_palletizing_patent_draft_2026-09-03.md` §3.5)에서
이미 도달한 결론 — **"(d) 안정성 + 로봇 IK/충돌 AND 게이트가 발명의 존재 이유"** — 와 정확히
같은 지점이다. 두 개의 독립적인 조사가 같은 결론에 수렴했다.

**진보성 리스크는 여전히 최대 항목이다.** "HD조선해양의 탐색 알고리즘을 3D 적층에 적용하면
안정성·파지 검사가 따라오는 것은 자명하다"는 반론에 대비해야 하며, 이는 문헌으로 막을 수
없고 **실험 데이터**로만 대응할 수 있다(§6-2의 4번). 구체적으로는
**"가상 회수 검증 없이 = 회수 실패·재배치 발생, 있으면 = 0"**을 같은 조건에서 보여야 한다.

**복수의 쌓여진 품목들 중 적어도 하나와 연관된 불안정성을 결정**,
③ **그 불안정성을 제거하는 위치에 품목을 배치**.

→ **"이미 쌓인 것들의 불안정성을 실시간 센서로 판정하고, 그것을 해소하는 위치를 고른다"**가
등록 청구항이다. D2(잔여물 안정성)와 D5(센서 되먹임)의 결합에 인접한다.
**단 회수(꺼내기) 개념이 없고, 판정이 힘 센서 실측이며 기하 시뮬레이션이 아니다.**

### 9-4. 라스테크 KR 10-2026-0007001 (등록) — D4 인접

비전(RGB-D 포즈 추정) → **MILP 기하 계획으로 다음 목표 포즈 산출** → **MPPI로 충돌 회피
궤적 계획**. 온라인. 타이어 대상.
→ **"기하 배치 계획 + 로봇 충돌 회피 궤적 계획"을 하나의 시스템으로 청구**한 등록건이다.
우리 S2·S6-②의 "배치 계획 + 경로 계획 결합"이 국내에 이미 등록돼 있다는 뜻이다.
**단 버퍼·회수·순서 제약이 없다**(버퍼 1회는 부수적 언급).

### 9-6. 비특허문헌(U10) — 확립된 학술 분야임이 확인됨

우려대로 **이 문제는 수십 년 된 학술 분야다.** 분야명은 **Block Relocation Problem(BRP)**
= Container Relocation Problem이며, 문헌들이 문제를 다음과 같이 정의한다.

> "**회수 과정 전체에 걸쳐 실행 가능성(feasibility)을 유지하기 위해**, 우선순위가 낮은 블록이
> 우선순위가 높은 블록 **위에 놓일 수 있으므로 블록의 재배치가 필요해질 수 있다.**
> 목적은 **명시된 순서로 블록을 회수하는 데 필요한 재배치 횟수를 최소화하는 적재 계획**을
> 찾는 것이다."
> — BRP 정식화 문헌([ScienceDirect](https://www.sciencedirect.com/science/article/abs/pii/S0377221711011337))

그리고 **적용 분야로 "창고 내 팔레트·박스·강판의 취급"이 명시**되어 있다
([exact algorithm 논문](https://www.sciencedirect.com/science/article/abs/pii/S0305054818301710)).
즉 **"우리 문제"는 이 분야에서 이미 정의된 문제의 한 사례로 읽힌다.**

특히 주의할 최근 문헌:
- **"The Static Buffer Reshuffling and Retrieval Problem for Autonomous Mobile Robots"**
  (Springer, [링크](https://link.springer.com/chapter/10.1007/978-3-031-71993-6_2)) —
  **"버퍼 구역의 재배치 + 생산 계획이 지정한 순서를 지키는 반송"**을 다룬다.
  **우리의 "외부에서 주어진 순서 + 버퍼" 프레임과 동일**하다.
- **"The Multi-AMR Buffer Storage, Retrieval, and Reshuffling Problem"**
  ([arXiv 2603.26542](https://arxiv.org/pdf/2603.26542))
- **"Physics-Aware Robotic Palletization with Online Masking Inference"**
  ([arXiv 2502.13443](https://arxiv.org/pdf/2502.13443)) — **물리 인식 + 온라인 마스킹**으로
  실행 불가 배치를 걸러낸다. **"실행 가능성 마스킹"이라는 우리 게이트 개념에 가장 근접한 최신
  연구**로 보인다. **전문 확인 필요(미완).**

**또한 무진의 상용 제품 설명이 선행 공개일 수 있다.** 무진은 혼합 케이스 팔레타이징에
"**지능형 버퍼 및 재시퀀싱**"이 소프트웨어에 내장되어 있고, **로봇 팔 옆의 테이블**에 케이스를
버퍼링하며, 케이스가 **팔레트 하단/중단에 적합한지 아니면 버퍼로 보낼지 판단**한다고 홍보한다.
→ §3에서 원문(선반·횡방향)으로 확인한 **"버퍼는 비적층"** 구조가 상용 제품에서도
**테이블(평면)**로 확인된다 — 우리 "적층 버퍼" 구별점을 **보강**한다.
다만 이 홍보 문구의 **공개 시점을 확정하지 못했다(미확인)**.

### 10-2. 그래서 무엇이 남는가

**개별 요소로는 아무것도 남지 않는다.** 남는 것은 **"어느 문헌도 이 조건 조합에서 이 게이트를
쓰지 않았다"**는 형태의 결합뿐이며, 그 결합의 각 항이 서로 필연적으로 얽혀야 한다.

**조건(전제) 3개 — 이 조합을 갖는 문헌이 없다:**
1. 버퍼가 **3차원 적층**이다 (HD조선·애자일소다·가치소프트·무진은 전부 평면/1열/스택테이블)
2. 그리퍼가 **상부 흡착**이라 **상면이 가려지면 대안 접근이 없다** (HD현대는 집게형 개방방향)
3. 회수 순서가 **외부 주문에서 주어져** 계획자가 바꿀 수 없다 (심보틱 재계획은 계획자가 배열을
   바꾼다, HD현대는 적재순서를 교체한다 — **둘 다 순서를 바꿔서 문제를 회피한다**)

**→ ①②③이 동시에 성립하면 "순서를 바꿔 회피"도 "다른 방향에서 집기"도 불가능하고,
남는 수단은 "애초에 놓을 자리를 바꾸는 것"뿐이다. 이것이 이 발명이 존재해야 하는 이유다.**

**게이트(해결 수단):** 가상 회수의 **매 제거 단계마다**
(a) 상면 노출·흡착 파지 가능성 · (b) 로봇+그리퍼+**들고 있는 박스**의 3D 무충돌 경로 해 존재 ·
(c) 제거 후 잔여 적재물 지지·전복 안정성
을 **AND로 검사하고, 하나라도 실패하면 그 배치 후보를 탈락**시킨다.
→ (a)(b)(c)를 **하나의 AND 탈락 게이트로 묶은 문헌은 없다**(개별로는 전부 존재).
